## 1. Coverage Governance & Verification Invariants

SENTINEL V6 adheres to an uncompromising, verification-first security philosophy. Every detected vulnerability must progress through a rigorous validation pipeline before being promoted to a confirmed Finding:

1. **COV-INV-01 (Proof Over Pattern)**: No vulnerability candidate may become a `Confirmed Finding` solely based on regex matching, header presence, or banner guessing. Automated verification or cryptographic proof is mandatory.
2. **COV-INV-02 (Deterministic Evidence Linking)**: Every finding must be immutably linked to Content-Addressable Storage (CAS) SHA-256 hashes of the exact Request/Response pair, DOM execution screenshot, or OAST callback log.
3. **COV-INV-03 (Negative Control Calibration)**: Before any mutating payload is evaluated, the engine MUST calibrate against an unmutated baseline request to identify baseline anomalies, dynamic tokens, and server jitter.
4. **COV-INV-04 (Scope-Gated Execution)**: All active probing, fuzzer mutations, and browser navigations are subject to the fail-closed `ScopeEngine` (SEC-01). Targets matching DENY rules or non-whitelisted hosts are immediately dropped.

## 4. False Positive Mitigation & Negative Control Architecture

To eliminate false positive alerts that plague legacy automated scanners, SENTINEL V6 implements a multi-stage validation filter before any candidate is promoted to a Finding:

### 1. Pre-Probe Baseline Calibration (Negative Control)
- Before transmitting active mutations, SENTINEL sends an unmutated baseline request.
- The baseline response status, length, headers, DOM structure, and latency are fingerprinted.
- Dynamic tokens (CSRF tokens, nonces, timestamps, session IDs) are automatically masked during differential analysis.

### 2. Multi-Round Oracle Inversion
- For blind injection (SQLi, NoSQLi, Boolean logic), SENTINEL requires a strict three-part assertion:
  1. `Assertion 1`: $Response(Probe_{True}) \equiv Baseline$
  2. `Assertion 2`: $Response(Probe_{False}) \neq Baseline$
  3. `Assertion 3`: $Response(Probe_{Inverted}) \equiv Response(Probe_{False})$
- All three assertions must succeed across 3 consecutive iterations.

### 3. Context-Aware AST Reflection Verification
- For XSS and template injections, SENTINEL parses the response HTML using a streaming HTML5/JavaScript tokenizer.
- It validates the exact context:
  - Inside HTML tag attribute (e.g. `<input value="PAYLOAD">`): Verifies quotes are broken out without escaping.
  - Inside JavaScript block (e.g. `<script>var x = 'PAYLOAD';</script>`): Verifies string boundary breakout or script block termination (`</script>`).
  - Inside raw HTML body: Verifies tags (`<script>`, `<img>`) are not HTML-entity encoded (`&lt;script&gt;`).

### 4. Dynamic Timing Baseline & Jitter Compensation
- For time-based blind vulnerabilities (SQLi sleep, CMDi sleep), SENTINEL computes the rolling average network latency ($\mu$) and standard deviation ($\sigma$).
- A time-delay probe of duration $T_{sleep} \ge 5\text{s}$ is only verified if:
$$T_{observed} \ge T_{sleep} + \mu - 0.5\text{s} \quad \text{AND} \quad T_{observed} \le T_{sleep} + \mu + 3\sigma$$
- A secondary verification trial with $T_{sleep} = 7\text{s}$ must also scale linearly ($T_{observed} \approx 7\text{s}$).

### 5. Cryptographic OAST Token Isolation
- Every OAST injection generates a unique 128-bit random nonce encrypted with AES-256-GCM.
- Callbacks are correlated strictly by decrypting the nonce and matching the exact project, task, endpoint, and parameter ID.
- Background internet noise, search crawler pings, and unsolicited DNS queries are immediately rejected.
