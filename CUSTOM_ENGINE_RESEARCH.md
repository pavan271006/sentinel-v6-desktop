## 2. Custom Engine 1: Security Context Graph

### 2.1 Theoretical Foundation & Node Taxonomy
Traditional tools treat HTTP requests as isolated transactions. The **Security Context Graph** represents every pentest engagement as a strongly-typed directed graph $G = (V, E)$ stored in SQLite CTE with Tantivy inverted indices:
* **Nodes ($V$)**: `Asset`, `Endpoint`, `Parameter`, `Technology`, `Identity`, `Session`, `Request`, `Response`, `State`, `Observation`, `Candidate`, `Verification`, `Evidence`, `Finding`, `OASTCallback`.
* **Edges ($E$)**: `EMITS_REQUEST`, `PRODUCES_RESPONSE`, `EXPOSES_PARAMETER`, `REQUIRES_ROLE`, `GENERATES_CANDIDATE`, `CONFIRMS_FINDING`, `SHA256_CAS_LINK`.

### 2.2 Invariant Constraints
* **Provenance**: Every Finding node must possess an unbroken path to a cryptographic SHA-256 CAS Evidence node (`SEC-07`).
* **Isolation**: Cross-project edge traversal is physically prohibited by SQLite foreign key partitioning (`SEC-03`).

## 3. Custom Engine 2: Adaptive Test Planner

### 3.1 Objective Function
The Adaptive Test Planner computes the next optimal test vector using an explainable information-gain optimization formula:

$$\max_{t \in T} \frac{\text{ExpectedRisk}(t) \times \text{Confidence}(tech, ver)}{\text{ResourceCost}(t) + \text{LatencyEstimate}(endpoint)}$$

### 3.2 Decision Reasoning (The "WHY" Engine)
Every test candidate generated by the planner includes structured explanation metadata:
1. **Target Technology Confirmed**: Confidence score (e.g., `PHP 8.2 (0.95)`).
2. **Preconditions Satisfied**: Authentication role present, endpoint in active scope (`SEC-01`).
3. **Budget Allocated**: Maximum permitted RPS and socket timeout bounds.

## 4. Custom Engine 3: Differential Security Engine

### 4.1 Multi-Dimensional Differential Analysis
Detects vulnerabilities by comparing response divergence across five orthogonal dimensions:
1. **Baseline vs Mutated Request**: AST structure, line count, reflection offsets.
2. **Identity A vs Identity B**: Role privilege matrix (BOLA/BFLA detection).
3. **Authenticated vs Anonymous**: Access control boundary verification.
4. **Protocol A vs Protocol B**: HTTP/1.1 vs HTTP/2 downgrade desync detection.
5. **Parser A vs Parser B**: Frontend reverse proxy vs backend origin URL normalization.

## 5. Custom Engine 4: Security Regression Graph

### 5.1 The Retest State Machine
When a vulnerability is remediated, the regression engine replays the exact verified transaction sequence:

```

```

## 6. Custom Engine 5: Engagement Memory

### 6.1 Deterministic State Preservation
* **Tested Paths Registry**: Prevents duplicate destructive testing of sensitive endpoints (e.g. `/logout`, `/delete_account`).
* **Verified Coverage Map**: Computes exact percentages of endpoints tested per OWASP category.
* **Cryptographic Audit Journal**: Lossless record of every socket emission with operator identity and timestamp (`SEC-12`).
