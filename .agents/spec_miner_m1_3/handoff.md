## 4. Logic Chain

1. **Premise 1 (Commercial Viability & License Safety)**:
   - SENTINEL V6 is an enterprise product requiring commercial permissibility.
   - Strong copyleft licenses (GPLv2, GPLv3, AGPLv3) impose viral source disclosure requirements if linked into proprietary binaries.
   - Therefore, all third-party security tools must be categorized by license type, and strong copyleft tools must be strictly quarantined to out-of-process subprocess adapters or clean-room native Rust re-implementations.
2. **Premise 2 (Native Rust Performance & Independence)**:
   - Spawning thousands of external Go/Python/Java processes (Nuclei, SQLMap, ZAP, FFUF) incurs massive process overhead, memory instability, and external runtime dependencies.
   - Therefore, core scanning, HTTP parsing, TLS probing, parameter discovery, and fuzzing must be natively implemented in pure Rust (`sentinel_scanner`, `sentinel_fuzzer`, `sentinel_proxy`), achieving 10x throughput and zero runtime dependencies.
3. **Premise 3 (Zero False Positives via Multi-Tier Verification)**:
   - Legacy automated scanners suffer from excessive false positives due to pattern-based matching without stateful proof.
   - Therefore, SENTINEL defines a 5-tier evidence hierarchy (CAS SHA-256 Request/Response, 3-sigma timing, AES-256 OAST correlation, DOM Playwright traces, and Multi-identity authorization matrices) backed by negative control baselines and 3-round oracle inversion.

## 5. Caveats

- Proprietary commercial tools (Caido, Burp Suite Pro) cannot have any code or proprietary assets integrated; integration is limited to zero-dependency clean-room architectures and open export format parsers (Burp XML/JSON, OpenAPI, HAR).
- Certain network-level tests (Naabu raw SYN scanning) require elevated OS privileges (`CAP_NET_RAW` / Administrator); when unavailable, SENTINEL gracefully falls back to unprivileged TCP connect probing.
